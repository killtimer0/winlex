# GUI 设计

## 结构与职责

GUI 使用原生 Win32 MDI，可同时打开多个实体或来源文档。

| 模块 | 职责 |
|---|---|
| `app.rs`、`app/frame.rs` | 应用组合、消息循环、后台结果分发和主窗口 |
| `app/workspace.rs`、`app/document.rs` | MDI 工作区、文档生命周期、排列和焦点 |
| `app/metadata.rs` | 元数据文档的绑定、内容与操作 |
| `app/sidebar.rs`、`app/panel.rs` | 侧栏、面板切换及面板内部交互 |
| `app/catalog.rs`、`app/sources.rs` | 加载事务、搜索状态、来源发现和管理 |
| `worker.rs`、`tasks.rs` | 通用后台执行机制与元数据任务 |
| `config.rs`、`app/settings.rs` | 配置存储、窗口与语言设置 |
| `dpi.rs`、`platform.rs`、`layout.rs` | 系统环境、字体度量和布局 |
| `input.rs`、`native.rs` | 系统对话框、拖放和原生操作辅助 |
| `resources.rs`、`res/` | 中英文资源及资源加载 |

窗口操作集中在 UI 线程。状态借用与可能重入窗口过程的 Win32 调用分开进行。
工作区、侧栏和文档内容分别管理自身状态；配置字段的语义由所属模块解释。

## 来源与文档

启动时使用显式 `--winmd` 列表，否则恢复保存的自动加载集合；首次启动为空。
CLI 的输入规则见 [CLI 文档](cli.md)。

添加文件、拖放和添加目录用于发现来源，加载操作由来源详情提供。
目录发现限于当前层的 WinMD 文件。用户加载或卸载来源会更新下次启动的加载意图；
临时命令行输入和加载失败不覆盖保存的意图。

来源按输入顺序保存在不可变 Catalog 中，实体由该快照内的来源索引和 token 定位，路径保留原生表示。加载成功后整体提交新的 Catalog，
失败保留已有数据。文档绑定打开时的内容快照，卸载或替换来源不改变旧文档。
实体文档固定查询架构，可通过“以另一架构打开”比较同一快照，通过“打开当前版本”查看更新后的来源。
符号显示名称、来源显示文件名，标题允许重复；路径和记录标识可在详情中查看。

## 交互与后台执行

MDI 管理文档激活，标签栏提供切换与关闭入口，窗口菜单提供排列操作。
侧栏负责面板显隐，面板负责内部焦点和导航。输入支持防抖搜索、Enter 执行和 IME 组合。

后台线程执行加载、发现和查询，UI 通过完成通知更新界面。任务执行机制与业务负载分离：

- 业务层按任务 ID 决定取消和替换关系。
- 替换释放旧的待执行负载，新任务排入队尾，其他任务保持相对顺序。
- 执行中的任务协作取消，过期结果由接收方拒绝。
- 结果队列有界，UI 分批处理完成消息，保持窗口消息响应。

文档关闭时取消相关任务。正在进行的文件读取或建库可能继续完成，UI 退出不等待磁盘操作。

## 系统环境与资源

应用统一持有系统版本信息，按系统能力选择原生功能。DPI 请求允许兼容降级，
界面依据实际生效的 DPI 等级布局，字体跟随系统设置。旧系统 API 兼容由 YY-Thunks 提供。
文件和目录选择使用对应系统的公共对话框，COM 接口采用类型化封装。

固定界面文案放在中英文资源中，资源和原生文本使用 UTF-16，动态业务文本按需转换。
菜单、加速键、版本信息和清单由 `gui.rc` 统一嵌入，资源 ID 定义在 `resource.h`。

## 配置与验证

配置保存在 `HKCU\Software\Winlex`，包括语言、窗口布局、来源位置及自动加载意图。
语言设置在下次启动生效，默认跟随系统，不支持的系统语言使用英文。
缺失或无效配置使用默认值；不支持的配置版本采用只读方式，避免覆盖已有设置。

测试可通过 `WINLEX_CONFIG_ROOT` 指定独立的 HKCU 相对路径，通过
`WINLEX_DPI=auto|pmv2|pmv1|system|unaware` 指定 DPI 请求模式。
测试配置与日常使用隔离，运行方式及兼容性验证范围见 [构建与验证](build.md)。
